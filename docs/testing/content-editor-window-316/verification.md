# 密码附加内容编辑窗口稳定性（1.0.316）

2026-10-02，普通版与 F-Droid 已接入。

## 用户现象和结论边界

录屏显示从新建密码的“添加内容”选择“笔记／备注”后，原密码页和备注编辑页在约 2.4–4.5 秒交叠、闪烁。截图中的 OplusViewMirrorManager 日志属于厂商窗口组件，单条日志不能证明根因。

公共 API 32 模拟器没有按原操作路径复现持续闪烁；原路径采样显示只创建一个编辑窗口。另一个最小复现确认：未聚焦输入框时，将所属列表卡片移出可见区会销毁编辑弹窗。修复前连续两次失败，均在 content_detail_NOTES 不再显示处失败。该机制与用户画面相符，但尚未在用户的 Oplus 设备上验证，不能宣称排除了全部厂商渲染问题。

## 修复

EntryContentPanel 的原生 Dialog 属于 LazyColumn 子项。输入框获得焦点之前没有自动保活，列表回收时会一起销毁窗口；卡片重新进入可见区，open 状态仍为 true，因而可以再次创建窗口。

编辑弹窗、更多菜单或删除确认打开期间，通过 LocalPinnableContainer 保留所属卡片；窗口关闭或整个编辑页面销毁时由 DisposableEffect 释放。未改动数据库、加密、备份、同步与保存格式，也没有关闭硬件加速、系统动画或安全保护。

本次为窗口生命周期修复，不更改视觉设计，未重新制作 Canvas 草图。

## 验证

- 复用公共 Monica_Issue136_API_32，API 32、x86_64。覆盖安装测试包，保留现有应用与 AVD 数据。
- 普通版、F-Droid 均通过 assembleDebug 与 assembleDebugAndroidTest（includeX86TestAbi）。
- 每版 2 项仪器测试通过，共 4 项：
  - 原始“添加内容 → 笔记”路径，逐帧采样 3 秒，只创建一个新原生窗口；编辑后返回再打开，草稿仍保留。
  - 未聚焦输入框时把父列表滚到远处，编辑器保持显示且原生窗口对象不变；关闭后卡片恢复正常回收，再次打开保留草稿。
- 最小复现修复前失败两次，修复后通过。基线日志来自普通版，修复后日志分别来自各发行版。
- 测试使用内存数据库与合成内容。测试脚本曾因在非主线程调用列表测量触发测试环境错误，已改为 Dispatchers.Main 后重新确认基线；这里仅保存修正后的有效结果。
- 生产代码没有新增诊断日志；窗口采样只在测试中运行。

结果见本目录 baseline-ui.log、baseline-repeat-ui.log、fixed-ui.log 与 window-trace.txt。

仍需用户机型与系统版本，并在相同设备上回测，确认原录屏中的闪烁是否完全消失。
