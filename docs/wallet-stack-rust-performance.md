# 卡叠批量归组与动画开销

## 处理边界

卡包排序已经使用 `RustListSortCore`。这次把卡叠归组也接入 `rust-jni`：

- 至少 256 张可见卡片且需要展示卡叠时，后台一次性打包卡片 ID 和保存的成员 ID。
- Rust 负责可见成员查找、组内去重、归组和输出索引。组间沿用当前列表首次出现顺序，组内沿用保存顺序，卡叠仍置于独立卡片之前。
- Kotlin 检查索引边界、数量、唯一性和完整覆盖，再用原卡片对象建立展示条目。封面、稳定 key、多选分区及搜索语义保留。
- 小批次、普通搜索的平铺模式、没有卡叠、原生库缺失、旧库缺少导出、native 失败和非法返回结果均使用原 Kotlin 路径。冲突的旧成员快照也回退，避免迁移改变既有行为。
- JNI 不接收卡号、密码、图片、标题或 `itemData`。卡片和卡叠持久化格式没有变化。

整个调用，包括 Kotlin 打包与返回映射，仍在 `rememberWalletStackEntries` 的 `Dispatchers.Default` 中。没有逐卡或逐帧 JNI 调用。

## 动画保护

`WalletStackBrowser` 原先每次父组件因当前卡片变化而重组时，都会执行 `cards.map { it.id }`。现在按成员列表缓存 ID 列表，用它作为焦点监听的 key；成员或顺序改变时仍会更新。

位置、阻尼、惯性、展开和收起插值、详情页转场继续由现有 Compose 实现处理。浏览器仍只组合附近最多 8 张卡，位姿在绘制阶段读取动画状态。

`WalletStackProjectionThreadTest` 用有访问计数的 5,000 张卡片快照调用真实的 `rememberWalletStackEntries`，打开卡叠并连续滑动三次，然后进入多选。它检查：

1. 归组打包和映射没有在主线程读取源列表；
2. 滑动动画与焦点重组没有再次读取源快照，也就没有重新打包 JNI 批次；
3. 多选模式改变仍然重新生成后台投影。

`WalletStackPerformanceTest` 另外计数浏览器对成员列表的访问，防止滑动重新引入全量扫描。原有浏览、详情返回、动画最终帧与底部封面交接、多选定位和分区测试继续覆盖视觉与交互行为。

## 测量方法

2026-09-11，专用 Android 12L / API 32 x86_64 模拟器，2 个 CPU 核、3 GB 内存、软件图形。Kotlin 使用 Debug 构建，Rust 使用 release 构建并以 x86_64 JNI 直接执行。数据均为生成的演示卡片，没有使用用户数据库。

归组对照使用同一个 APK 中保留的 Kotlin 实现与完整 native 路径，涵盖 64、256、1,000、10,000 张卡，两种布局和普通/多选模式。多个卡叠场景每 20 张卡中有 16 张归组；单个大卡叠场景约 80% 卡片归组。卡片列表以固定种子打乱，保存的成员顺序倒序。

每项先预热 10 对，再采样 21 对，并交替先执行 Kotlin 或 Rust。Rust 时间包含打包、JNI 复制、原生归组、结果验证和对象映射；不单独用 Rust 内部循环时间代替完整开销。首次动态库加载不包含在预热后的结果中。

这些是模拟器组件测量，不能换算为真机首屏速度、FPS 或掉帧率。动画保护的证据是后台线程与重复工作检查，以及现有动效回归；没有宣称真机帧时间数据。

## 验证结果

- 18 项 Rust JNI 单元测试、rustfmt 和严格 Clippy 通过，ARM64、ARMv7、x86_64 release 原生库编译通过。
- 32 项 JVM 测试通过，包含原有归组、多选、位姿、卡片排序与新增 native 返回验证、缺库回退。
- 39 项 Android 测试通过：6 项性能、真实 JNI 对照与线程检查，33 项浏览、导航、多选、持久化、原有 Rust 排序与 KDF 回归。
- 动效回归覆盖拖动、惯性中途收起、详情返回焦点、返回期间触摸与返回键归属、底部卡片与动画最后一帧的像素/边界交接、多选展开后的滚动定位。
- 应用包为 `1.0.311-26091112-06`，`versionCode` 保持 12；三个 ABI 均校验了版本、原签名、JNI 导出和 APK 内原生库的哈希。

第一次新增浏览器基线测试漏放 overlay host；第一次线程测试只在 `SideEffect` 内读取投影，导致多选时没有订阅状态更新。修正测试搭建后复验通过。最后只重新编译了测试 APK，主应用与原生源码保持与完整构建时一致，没有跳过源码编译。

## 复现

```sh
cargo fmt --manifest-path rust-jni/Cargo.toml --all -- --check
cargo clippy --manifest-path rust-jni/Cargo.toml --all-targets --all-features -- -D warnings
cargo test --manifest-path rust-jni/Cargo.toml --all-targets --all-features
cd rust-jni
cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -o ../app/src/main/jniLibs build --release
cd ..
./gradlew -PincludeX86TestAbi :app:assembleDebug :app:assembleDebugAndroidTest
```

安装 x86_64 应用包和测试包后运行 `WalletStackPerformanceTest`、`WalletStackNativeProjectionTest`、`WalletStackProjectionThreadTest`。测量结果写入应用的外部文件目录 `wallet-performance/projection-comparison.json` 和 `browser-optimized.json`，包含逐次样本。

本地仓库位于另一个 Cargo workspace 内，所以验证时把 `rust-jni` 与 `rust-crypto` 原样复制到一个隔离 workspace；最终校验源文件哈希与打包的原生库。CI 在仓库自己的路径直接执行上述命令。生成的 `.so` 不提交。
