# WebDAV 全量备份后 MDBX 同步遇到 503 的排查

日期：2026-10-01；版本：1.0.315（未发布）。

## 结论与边界

用户截图显示备份目录查询收到 HTTP 503。它表示服务暂不可用，单凭状态码无法区分服务异常与请求限流，也不能推断已上传的备份损坏。

已通过真实 `WebDavHelper`、HTTP 测试服务器和 MDBX WebDAV 客户端复现以下顺序：

1. 查询备份目录并成功上传归档（PUT 201）。
2. 后续旧备份清理查询收到 503 和 `Retry-After: 300`。
3. 上传结果保持成功，同时记录清理警告。
4. 相同主机的 MDBX 同步被共享冷却状态阻止，不再发网络请求。

因此，“全量备份成功”与“之后需要等待再同步”可以同时发生。尚无此次手机操作的完整请求日志，不能断言其触发限流的具体请求与测试完全一致。本轮未访问用户的坚果云账号。

## 修复

- 原列表读取先用 PROPFIND 判断目录存在，再用 PROPFIND 读取列表；改为一次列表查询，仅 404 视为空目录。401、503 等错误继续保留。
- 页面首次进入与后台备份完成共用一个刷新 effect，运行中不抢先查询，进度更新不触发列表请求；同时合并尚未结束的刷新。
- 刷新失败保留已经显示的备份列表，展示错误，不用空列表覆盖。
- F-Droid 保留原有明文 HTTP 显式开关和默认防护。

未调整备份格式、恢复流程、自动清理策略或同步内容。上传成功不会清除其他请求触发的冷却；继续遵守服务端等待时间，不通过快速重试绕过限制。这能减少不必要的请求，不能保证服务端不再返回 503。

- 请求顺序测试使用隔离设置和合成数据，涵盖成功上传、清理 503、共享冷却、正常上传后 MDBX 请求和错误目录状态。
- 普通版与 F-Droid 均完成 Debug APK 和设备测试 APK 构建。
- 两版各 20 项 JVM 测试通过：并发冷却 3 项、503 退避 2 项、MDBX 目录 2 项、保留策略 13 项，无失败或跳过。

- 页面刷新归并与失败保留列表完成代码检查；本轮设备用例覆盖 helper／HTTP 链路，没有将其当作页面交互自动化测试。
- 两版及各自候选目录的本次源码、测试和中英文未发布说明已同步；F-Droid 发行说明不包含 OneDrive。
