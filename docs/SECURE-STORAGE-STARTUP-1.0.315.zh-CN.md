# Keystore／加密配置启动保护（1.0.315，未发布）

## 可以确认的事实

用户提供的片段显示 EncryptedSharedPreferences 在 Activity 启动时发生 AEADBadTagException，底层为 Keystore MAC 验证失败。隔离测试篡改测试 keyset 的认证标签，连续两次复现同类异常；原来的 SecurityManager 构造直接抛出，MainActivity 没有启动保护分支。

这证明需要补充容错，不证明用户设备的密钥失效由 Monica、root 或 keybox 中的哪一个造成。恢复应用数据、系统／密钥环境变化、密文损坏或临时 Keystore 故障均需结合完整日志和操作历史区分。keybox 与用于加密配置的 AES 主密钥不是同一概念。

Monica 的 MasterKey 没有设置用户认证要求；不能笼统认定修改锁屏密码必然让它失效。清单已禁用 Android 自动备份，但 root 工具仍可能复制应用私有数据，复制密文也不等于复制有效的系统密钥。

## 数据保护原则

- 不将认证失败当成首次安装，不回退到明文或空配置。
- 不自动删除配置、密钥、数据库或备份，不提供“清空全部数据”作为修复入口。
- 打开前检查现有 keyset 与主密钥。旧配置缺少主密钥或 keyset 时，不生成替代品。
- 已有配置文件但读成空内容时阻止初始化，避免覆盖损坏文件。
- 验证 keyset 后读取全部加密配置，避免某个坏值在正常启动后才触发错误或被解释为无凭据。
- 正常打开密码库之前完成预检；异常页面只提供重试、退出和脱敏诊断。本次启动的同步观察、上传恢复与附件维护等待预检成功；健康的后台启动仍可独立完成检查。
- 重试不清空任何磁盘数据；原密钥环境／配置恢复有效后可正常启动。永久丢失的系统密钥无法凭空恢复。

## 用户建议

保留原文件，先重启并使用系统锁屏凭据解锁。如果此前恢复数据、刷机或修改系统，可检查能否恢复原环境。不要清除应用数据或卸载。已有 Monica 导出备份应先在另一安装中验证恢复。

## 验证范围

测试全部使用独立 SharedPreferences 名称及专用临时文件；删除密钥仅用于测试自己创建的随机别名，不操作用户主密钥。覆盖 keyset 校验失败、主密钥缺失、keyset 缺失、单值损坏、空读文件保护、Bitwarden 配置异常、正常读写、原配置恢复后重试、健康后台启动和保护页交互。尚未在用户实际 root／keybox 环境复现，不能据此认定该设备的根本诱因。

最终结果见 secure-startup-315-verification.json；界面与可编辑 Canvas 链接见 design/secure-startup-315/README.md。在线 Canvas 渲染未验证。

## 最终验证结果

普通版与 F-Droid 均构建成功，在公共 API 32 模拟器上分别通过 11 项仪器测试（合计 22 项）。覆盖并发首次打开及上述故障保护；浅色／深色、1.5 倍字体的原生截图已检查。测试使用隔离配置，未验证用户实际 root／keybox 环境。两版源码与候选公共修复文件 SHA-256 一致。详细日志保存在工作区 `.codex-tasks/secure-startup-315/`。
