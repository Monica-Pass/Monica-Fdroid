# MDBX 无编辑时待同步误报修复（1.0.315，未发布）

## 用户现象与复现

手动同步后“未同步”消失，但重新进入应用、浏览详情或等待后台检查后再次出现，没有新建或编辑项目。

在公共 Android 32 模拟器上，用独立合成 MDBX 库、真实 Rust 引擎和持久 Room 同步游标复现了两条路径：

- 同步完成后只将连接检查结果设为 FAILED，原待同步计数返回 2，而没有任何新提交。
- 对已存在的文件夹重复设置同一组标签，原会话结束逻辑仍把 IN_SYNC 改为 PENDING_UPLOAD；无候选项的快照整理存在相同问题。

“只看详情”本身不应修改内容。回归测试还覆盖真实 `MdbxViewModel.activateMdbxDatabase()` 的导入投影和预加载，再读取密码/API 令牌详情、销毁 ViewModel 后重建，检查该过程没有制造待上传编辑。

## 修复边界

1. 同步状态描述最近一次尝试的结果，不能直接作为“有未上传项目”的证据。读取计数前对照 Rust 不透明提交检查点，不再只依赖设备时间和历史记录估算。
2. 传输 JSON 游标新增可选 `syncedCommitInventory`，记录已发布或安全接收的提交。旧游标缺少字段时回退到已确认的 `exportCheckpoint.commitInventory`，并验证 vault ID。未确认的同步不能把当前库头直接记成已同步。
3. 完整 `exportCheckpoint` 仍包含审计增量。只读授权/拒绝记录保持在正常同步流里；可见待修改状态与审计传输游标分开，不删除审计、不伪造已上传。
4. 写会话只在原生提交实际变化时完成待上传标记。检查与标记仍位于同一数据库编辑锁内；移除释放编辑锁后重复写入的标记，避免覆盖稍后完成的同步状态。批量导入已提交部分的确认逻辑保留。
5. 列表复用现有状态胶囊和同步按钮。FAILED、REMOTE_CHANGED 不再强制把 0 变成 1；分别显示现有翻译“同步失败”“远端变化”，冲突单独提示，保留重试。真实 PENDING_UPLOAD 仍防止旧缓存中的 0 隐藏新编辑。

没有修改 MDBX payload、加密方式、原生文件格式、备份格式或 Room 表结构；没有清除用户数据、配置、审计、冲突或同步流。版本保持 1.0.315，普通版 versionCode 12、F-Droid 22。

## 回归覆盖

- 空操作：相同标签、空快照整理、重复列出文件夹/快照/诊断。
- 重开：同设备身份新建 repository，清空仅内存原生读会话，重新读库；实际 ViewModel 激活与详情读取反复三轮。
- TiGA：Sky、Multi 读取；Power 的普通测试设备仍按原策略拒绝敏感披露，拒绝操作不能成为用户编辑。此测试不声称 Power 的增强设备授权流程已被覆盖。
- 审计：提交未变化时计数为 0，完整游标不被提前推进，下次同步确实上传审计增量。
- 正向写入：新密码、标签、快照创建/删除在失败状态下仍待上传，成功发布后才清除。
- 并发：网络请求等待时仍能读取详情；下载期间和完成确认前的编辑保留待上传，下一次同步送达另一副本。
- 兼容：旧 JSON 游标可读取；错误 vault ID 不能用于隐藏修改；状态序列化重启保留新字段与旧传输检查点。
- WebDAV：经本机隔离 HTTP WebDAV 服务和 Android 正式传输适配器测试引导下载、双端同步、附件、冲突及重开，非单纯内存网络替身。仅使用合成凭据和测试数据；不等同于验证用户实际服务商的网络环境。
- UI：中英文状态文字与同步按钮可用性，失败不显示“未同步 0 条”，成功后错误状态消失。

构建、测试计数、原有数据对比及四份代码一致性见同目录 `mdbx-idle-sync-315-verification.json`。完整排查与运行日志位于工作区 `.codex-tasks/mdbx-idle-sync-315/`。
