# 密码库滚动条性能核查（1.0.315 未发布）

## 修复范围

- 拖动位置从组合阶段移入 `snapshotFlow`、布局和绘制阶段，避免每个指针事件重新组合并重启动画任务。
- 提示文字使用派生状态，只在分组文字变化时更新；文字尺寸按文字、样式和测量器缓存，仍适应系统字体及完整日期。
- 日期分组与当前位置改为二分查找，避免每次滚动扫描之前的全部分组。
- 主页面将浮动快速滚动面板的标签作为延迟读取函数传递；面板隐藏时不读取它，避免日期变化刷新整个主页面。
- 保留原有逐帧合并位置请求、不同高度卡片的稳定坐标、两端定位和松手后的最后一次位置请求。外观及存储格式不变。

## 可重复证据

`ExpressiveScrollbarInteractionTest.movingInsideTheSameRowDoesNotRecomposeTheScrollbar` 在同一行内连续移动指针 20 次：修复前产生 20 次额外组合；修复后为 0 次，列表偏移仍然随手指变化。

`VaultV2ScrollLookupTest` 覆盖 4096 个日期分组。旧代码查询第 1025 组需访问 1025 组并触发性能断言；新代码每次至多访问 13 组。另行核对前置控件、分组标题、空列表和尾部位置，映射结果保持一致。

## 帧测量的边界

`VaultScrollbarPerformanceTest` 使用 Android 真实帧时钟、FrameMetrics 和触摸事件；在内存中生成 3000 张真实密码库卡片并混合行高，预热后执行三轮往返拖动。测试不向密码库写入条目。

API 32 公共模拟器的 debug 构建测量存在明显波动：基线三轮 P95 为 40.66–50.31 ms，首轮优化后三轮为 40.95–51.55 ms，区间重叠。因此没有宣称固定的帧率增幅或彻底消除所有设备的掉帧。能确定的是重复组合被消除、日期查找复杂度由线性降为对数。大跨度拖动仍需创建及绘制新卡片；该环境不能准确代表实体机 release 构建性能。

当前热点涉及 Compose 组合、观察和绘制调度，定位计算已使用前缀树及二分查找，无证据支持为这次问题新增 Rust/JNI 路径。

## 验证

普通版与 F-Droid 的单元／设备测试、数据一致性检查见 `vault-scroll-performance-315-verification.json`。逐行移动、混合高度单向连续性、顶部／底部松手定位以及完整日期显示均纳入回归。四份对应源码同步；版本号维持 1.0.315，未创建提交或发布。
