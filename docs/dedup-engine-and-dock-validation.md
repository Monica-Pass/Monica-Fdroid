# 去重整理与 Dock 性能

## 操作与数据范围

[可编辑 M3E Canvas 草图](design/dedup-engine-m3e.md)包括配置、明细和数据库选择。原生页面采用左右 12dp 留白、连接式圆角操作组、可搜索的懒加载弹层和固定主操作。明细可筛选新增、冲突、跳过，展开时显示来源与所采用的版本，不展示密码。

去重是将来源整理后写入独立目标。支持一个或多个来源；目标支持 Monica 本地和 MDBX，KeePass 与 Bitwarden 可作为来源。它不删除来源，也不覆盖目标已有内容。目标账号相同但内容不同时另存副本；完全一致才跳过。写入前再次检查目标，取消或替换扫描后不能执行旧计划。

判重保留 URL 路径大小写、非邮箱用户名大小写和密码空格。OTP 的类型、算法、周期、位数、counter、PIN 都参与身份比较。受保护的自定义字段按解密后的值比较，同名不同值保留。卡片等内容比较完整 JSON，包括新字段和未知字段，比较时解密，写入时保留原来的加密数据。

MDBX 写入密码后，待自定义字段取得新记录 ID，再刷新完整条目；失败时沿用回滚。「内容更完整」会比较卡片内容中的实际字段，而不是仅判断整个 JSON 是否非空；选中的卡片 payload 整体保留，不声称能自动补齐任意嵌套字段。

独立附件也参与内容判重，使用文件名、类型和内容摘要区分；相同内容合并，同名不同内容均保留。复制复用附件子系统，为目标创建独立密文；缺失、解密失败或复制期间内容变化时，撤回该条目及已复制的附件，保留来源，其他成功条目仍可保留。附件元数据按 800 个 owner 分批读取；未知摘要按流计算，不把整批附件装入内存。

旧式照片复制为独立的加密图片，写入 MDBX 时同时保存为标准附件。重新读取 MDBX 后可恢复缺失的照片文件，保持原有图片引用不变；自定义卡面沿用现有附件名。图片读取限制仍为 25 MiB，并在读取密文前检查大小。

空的正反面图片槽不计入完整度，也不会遮住另一份来源中的真实照片。MDBX 恢复照片按 800 个记录 ID 分批查询，仅处理带图片引用的项目。

Passkey 使用规范化后的 credential ID、RP ID、用户句柄、公钥、私钥指纹及关键元数据判重，保留不同注册凭据。仅复制具有可用密钥、未绑定密码、签名计数为零的凭据；设备绑定密钥可保留在本机，但不伪装成可移植密钥写入 MDBX。非零计数、引用、不可用密钥、已绑定密码及身份冲突在明细中显示原因。相同 credential ID 但密钥、备注或关键元数据不同的记录交由用户核对，既不覆盖目标，也不推测哪把钥匙正确。写入复用 PasskeyRepository，不修改认证或签名计数逻辑。

Passkey 批量移动仍受原有目标兼容条件限制。修正了 Bitwarden 到 MDBX 批量路径的写入顺序：目标持久化成功后才排队删除来源；目标失败或取消时不排来源删除。删除本地副本时，只有不存在其他记录引用同一私钥才清理密钥，避免删除副本破坏保留的凭据。

## Dock 的具体开销

连续切换密码、验证器、卡包、设置时，原来卡包和验证器每次进入都会创建 `SecurityManager`，在主线程重新打开 MasterKey / EncryptedSharedPreferences。一次 28 次切换的方法采样中，这些构造调用累计约 395ms CPU 时间。该采样用于定位热点，不用于帧率对比。

现在列表页复用 Activity 已初始化的实例。加密实现、锁定流程和 Passkey 签名行为未改变。独立预览和测试宿主仍可建立自己的实例。

修改后的相同操作采样中未再出现这些构造调用。整页帧率的模拟器样本波动较大：旧样本卡顿帧 9.05%，新包刚安装后的样本为 85.65%，后续未采样的稳定运行样本为 11.28%。因此不以这些帧率宣称整体流畅度提升了某个百分比，也不把方法采样期间的帧率混入对比。

密码页原先即使拿到保留的分组，也会再次计算。现在区分完全一致与仅结构兼容的缓存：只有完整输入及配置一致才跳过；手动堆叠信息或列表变化仍刷新，锁定时按原生命周期清除缓存。

## Rust 分组

大列表一次打包数字元数据，Rust 完成两阶段归组、收藏与卡片类型评分、稳定排序并返回源索引。URL 和字符串规范化仍采用原 Kotlin 规则；标题排序发送 UTF-16 排名。密码、标题、网址、用户名等字符串不传入 JNI。

保持手动堆叠、不堆叠、API 令牌独立身份、同分排序、展开模式与本地平铺的既有语义。回退算法也缓存每组评分，避免在排序比较器中反复解析网址和遍历整组。

普通分组在后台执行；同步组合阶段的「未堆叠」快捷筛选使用优化后的 Kotlin 路径，不在该路径加载 JNI。

单批最多 200,000 条，JNI 在分配前检查长度、数量和索引；Rust 使用有上限且可报告失败的分配。Kotlin 验证输出长度、边界、不重复和完整覆盖。旧原生库、原生失败、超限或无效结果回退到 Kotlin。没有新的持久缓存或凭据序列化格式。

## 验证方法

复用 `Monica_Issue136_API_32`，API 32 / x86_64 的公共模拟器，在现有独立测试用户中运行；数据来自合成测试库。ADB 操作只针对该设备。

- Room 实际读写检查来源不变、冲突副本、自定义字段、OTP、重复执行、取消与过期计划。
- 使用真实 Rust MDBX 文件，清除 native 读取会话后重开，核对密码、自定义字段、笔记和 Passkey，并用读回的私钥独立签名、验签。
- Passkey 测试检查跨来源重复、同账号不同钥匙、身份冲突、非零计数、绑定密码、设备绑定私钥、重复执行，以及删除副本后原凭据继续签名。测试不包含真实网站账号或真实 Bitwarden 服务器。
- 数据库组合测试使用实际导入流程创建本地、KDBX、MDBX 与模拟 Bitwarden 来源，覆盖七种有效组合以及四库混合整理。每种组合检查密码、笔记、OTP、卡片、独立 Passkey、密码附件和笔记附件；再次执行应新增 0 条，来源记录、KDBX 文件及模拟服务端 Cipher 不变。
- 故障测试检查无法解锁的目标、缺失和损坏附件、附件复制后的回滚，以及目标缺附件时不能误判为完整副本。另检查照片与卡面独立复制、MDBX 内的图片附件及本地图片恢复。
- 3000 条来源密码与 3000 个字段整理为 1500 条新密码、1500 个字段，再执行新增 0 条。大批量样本使用合成内容，不能代表任意真实数据库的解密或同步耗时。
- 分组以原实现作为独立对照，比较完整的组顺序和成员顺序。性能时间包含 Kotlin 规范化、打包、JNI、返回校验和对象映射。
- Dock 对比均预热两轮，再按相同顺序切换 28 次；采样分析与帧时间测量分开，帧时间测量时不运行构建。

模拟器和 Debug 构建的测量不能换算为所有真机的流畅度。这里未测试真实远端同步速度，也没有据此声称所有设备或任意规模数据都已验收。

## 数据库组合结果

| 来源 | 整理到本地 | 整理到 MDBX |
| --- | --- | --- |
| Monica 本地 | 同源同目标被阻止 | 通过 |
| MDBX | 通过 | 通过，使用另一数据库 |
| KeePass / KDBX | 通过 | 通过 |
| Bitwarden | 通过 | 通过 |

四类来源混合整理、重复执行、同名不同内容的附件、缺附件的目标、损坏或缺失附件、目标无法解锁、照片和卡面，以及无缓存时从 KDBX / Bitwarden 获取附件，均完成验证。Bitwarden 使用模拟服务，包含真实的 Cipher 和附件加解密、临时下载地址及文件下载接口，不代表真实服务端或网站账号验收。

本轮覆盖 48 项不同的设备检查：15 项数据库与媒体场景、30 项去重 / Passkey / UI 检查、3 项原生分组检查。失败场景修正后只重跑受影响的检查，按各项最新结果核对为全部通过。主版本与 F-Droid 各 25 项相关 JVM 测试通过，两个版本的 Debug 包及测试包均编译通过；另有 5 项 Rust 测试、Clippy 检查及三种 ABI 的原生库编译通过。

## 分组测量结果

API 32 / x86_64，Debug，合成数据。每种规模预热 3 次，再轮换测量 9 次，以下为完整调用的中位数（毫秒），包括 JNI 打包和返回映射。

| 条目数 | 原 Kotlin 实现 | 优化后 Kotlin | Rust 完整路径 |
| --- | ---: | ---: | ---: |
| 256 | 66.06 | 11.65 | 6.94 |
| 1,000 | 245.78 | 31.26 | 21.59 |
| 10,000 | 2,336.49 | 225.73 | 230.80 |

主要收益来自消除重复归组、评分及网址解析。Rust 在此 10,000 条样本中与优化后的 Kotlin 相近，不声称所有规模都更快。[原始测量](dedup-grouping-api32.json)。
