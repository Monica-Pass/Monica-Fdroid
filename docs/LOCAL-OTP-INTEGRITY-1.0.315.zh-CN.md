# 本地验证器升级与恢复排查（1.0.315）

反馈现象：更新后验证器列表消失，第一次恢复没有显示，再恢复一次后出现。没有用户的升级前后版本、备份类型、数据库或日志，尚不能确认该用户的具体根因；不能据此归因于误操作，也不能保证所有设备永远不会丢数据。

## 已复现的问题与修复

| 路径 | 复现证据 | 处理 |
| --- | --- | --- |
| 覆盖恢复 | ZIP 解析成功后、尚未调用写入阶段，原本地 OTP 已被删除；负向测试只在外层回滚事务内运行，未持久化清除公共 AVD 数据 | 解析只返回覆盖意图；本地条目清除与实际写入放在同一 Room 事务，失败和取消回滚；关联字段/附件的补充写入失败也中止覆盖 |
| 合并恢复去重 | 同一账号更换密钥，或同一密钥更换位数、算法、周期、恢复资料时，被计为重复并跳过 | TOTP 恢复要求完整有效载荷与备注/标题匹配；补齐旧格式默认值后比较，忽略需重新映射的绑定 ID，保留未识别字段 |
| 列表解析 | `secret` 为对象时抛异常；解密失败时把密文当作明文密钥返回 | 单条异常保持隔离，不终止共享列表；不缓存解密失败的结果；解锁状态变化后重新解析 |
| 后台加密迁移 | 真实 DAO 读取批次后插入一次用户编辑，旧实现把新值覆盖回旧值的密文 | 使用 SQL 条件更新，仅在值仍等于批次读取值时迁移；保持小批次和不触发同步的行为 |
| 密码绑定重映射 | 含嵌套未知字段的 OTP 备份恢复后，字段消失，真实恢复测试报 `No value for futureRecovery` | 只修改原 JSON 中的绑定字段，不再反序列化后整份重建；重复恢复仍可去重 |

## 验证方法

所有测试仅使用合成密钥。复用 `Monica_Issue136_API_32`，没有清除应用数据、创建新 AVD 或更改主密码。数据库替换测试使用独立内存/临时数据库；共享库中的覆盖路径测试有强制回滚外层事务。

- JVM：解析失败、无解密器、重新解锁后重试，以及已有 OTP 类型/URI 和导入保护测试。
- Android：真实 `WebDavHelper` → `BackupRestoreApplier` → Room；重复恢复、密钥轮换、参数/资料保留、失败不改原记录。
- 列表：真实 `TotpViewModel.parsedTotpState`，同时放入正常 OTP、损坏 OTP 和不可解密的密码 OTP，验证正常项仍可读，后续修复写入仍刷新。
- 覆盖：成功写入并重开；异常、失败计数、取消均回滚；保留外部数据库行及级联自定义字段。
- 升级：建立完整 schema 77 数据库（按当前结构去掉 78 新增的三个 KeePass 密钥文件字段/索引），用实际 77→78 迁移打开，再关闭重开。检查五种 OTP、密文原值、密码绑定字段、回收站标记、自定义字段及代码生成。
- 并发：在真实 DAO 返回旧批次后写入新密钥，再运行真实迁移管理器，验证独立和绑定 OTP 均保留新值，未编辑项正常迁移。

## 验证边界

这不是用户原始数据库的复现，也不是所有历史 Android 版本/厂商设备的升级证明。已保存的数据库、分类和搜索筛选可以使列表变空，应先核对“全部”视图；本次没有随意重置用户筛选。没有发现本次接入引入删除本地 OTP 的 Room 结构迁移，数据库没有启用破坏性重建兜底。

事务保证覆盖的是本地 Room 记录及其关联表。文件附件的物化、设置恢复及 Steam 的独立数据库不组成单个跨文件分布式事务；Steam 在独立事务中处理，新增附件失败可能留下可清理的孤立密文文件，不删除原附件文件。Android Keystore 永久失效、存储介质损坏、卸载或用户主动删除等情形不能靠本补丁承诺自动恢复。
