# WebDAV 全量备份 Passkey 排查（1.0.315，未发布）

## 反馈与结论边界

用户反馈包含 Passkey 的全量备份被“不完整备份”检查阻止，取消 Passkey 后成功。尚未取得准确 Monica / Android 版本、密钥来源及具体失败项，因此不能确认该用户的根因，也不能宣称所有同类问题已修复。

已用 Android 32 公共模拟器构造正常 PKCS#8、受保护私钥引用、缺失的私钥引用和 AndroidKeyStore 不可导出密钥。缺失或不可导出的密钥会导致备份报告不完整；关闭 Passkey 可使相同测试的备份成功。不可导出是设备密钥的限制，不能通过绕过检查得到可迁移的私钥。

## 本次修改

- 全量备份保留具体失败报告，M3E 弹窗列出失败项目、原因和解决建议，内容滚动、操作固定在底部，支持重试或明确跳过问题 Passkey。异常消息和新增诊断日志不包含项目名称或私钥。
- 区分私钥缺失 / 格式不识别、受保护私钥读取异常、不可导出的设备密钥。
- 旧 alias 只有取得可导出内容且通过 PKCS#8 验证后才能进入加密备份。未加密时仍拒绝导出 Passkey。
- 单条私钥读取异常记入该条失败项，继续检查其他条目；整个备份仍判定不完整。
- `createAndUploadBackup` 外层保留带报告的异常，让具体原因到达设置页面。上传及远端保留策略清理仍在完整性检查之后。
- 不删除本地条目，不自动跳过失败密钥，不恢复已经丢失的私钥。F-Droid 的不安全 HTTP 开关保持原有实现。
- 用户明确跳过后，仅过滤选中的问题 Passkey，正常 Passkey 仍备份；其他失败仍阻止上传。加密 ZIP 内记录 `monica_partial_backup.json` 遗漏清单，远端文件带 `_partial_<UUID>_permanent`，避免同秒覆盖并保留为永久备份。
- 部分备份不执行远端保留策略清理，不更新上次完整备份时间；完成弹窗明确说明遗漏项。恢复读取 ZIP 内标记，禁止替换本地数据，仅支持合并恢复（即使文件被重命名，标记仍生效）。

## 验证

`PasskeyBackupFailureInstrumentedTest` 覆盖两组场景：

1. 实际生成加密 ZIP：正常与受保护私钥导出成功，缺失与设备绑定密钥给出相应失败原因；完整上传入口保留具体失败项。通过假的 Sardine 客户端验证：只跳过一个失败项时仍不联网；跳过所有问题 Passkey 后仅执行 `exists` / `put`，不清理旧备份、不更新完整备份时间；上传产物禁止覆盖恢复。关闭 Passkey 后生成成功，四条测试记录仍存在。
2. 旧 alias 回退：合法 PKCS#8 字节保持一致，无效材料拒绝导出，未加密时不读取密钥。

`BackupProblemDialogTest` 检查原因与方案、明确点击后才跳过、重试和关闭、大字体长列表操作可达、部分备份完成提示，以及非 Passkey 失败不能被跳过。真实渲染截图和可编辑 Canvas 见 `design/passkey-backup-315/`。

测试只插入并清理 UUID 标识的测试条目和测试密钥，上传测试使用实例内配置，不修改设备保存的 WebDAV 设置。失败备份在联网上传之前被阻止。本轮使用假的远端客户端捕获真实加密上传产物，没有连接真实 WebDAV 服务，也没有取得用户实际数据库。

最终两版构建及设备结果、APK 哈希记录见同目录 `webdav-passkey-315-verification.json`。共享测试设备为 `Monica_Issue136_API_32`，复用原有运行实例。

## 后续诊断

新版本重试后可根据具体失败项目区分缺失私钥、读取失败或设备绑定密钥。只需反馈脱敏后的错误原因、准确应用 / Android 版本及导入来源；不需要提供私钥或完整密码库。
