# 验证器卡片布局验证

## 布局规则

- 磁贴沿用 313 的紧凑外观：普通字号固定 142dp，内边距 12dp，内部间隔 8dp；同一设置下外框等高。
- 有账号才显示副标题，无账号不插空行，不强制左右验证码对齐。
- 当前验证码完整、单行显示，宽度不足时缩小。下一组码正常显示；空间紧张时逐步缩小，仍放不下则隐藏。只有标题与当前码也无法容纳时，才统一增高外框。
- 正常列表保留 Next，实际卡片边缘间距为 8dp；删除了原先叠加的第二份 Spacer。
- 隐藏当前验证码时同时遮罩下一组，复制返回完整原始码。

[可编辑 M3E Canvas](design/authenticator-card-layout-m3e.md)

## 修复原因

先前把 `lineHeight.toPx()` 之和当作真实文字高度，忽略了字体度量与实际排版时的缩放差异。API 32、320dp、1.5 倍字号的复现中，估算标题行高约 68px，实际为 83px；当前码只得到 44px，却需要至少 95px。Column 优先测量不带 weight 的下一组码，让带 weight 的当前码被裁切。

现在用 Compose TextMeasurer 的实际段落高度计算共用预算，当前码先测量；预览按完整行是否能容纳选择字号或隐藏。没有通过添加空副标题或提高所有普通磁贴来对齐内容。

## 验证

Debug 应用和测试包构建通过（15 分 31 秒）。公共 API 32 x86_64、320dp 屏宽上 9 项相关用例已覆盖通过：首轮 8 项通过，原有磁贴菜单用例遇到 Compose 测试时钟跨线程异常；同一安装包单独重跑该用例通过（11.307 秒）。没有为这次测试异常修改生产时钟或放松布局断言。

已检查普通字号、1.3 倍与 1.5 倍字号原生截图：两卡均为 142dp；无账号时验证码自然上移；当前码完整显示，1.3 倍字号缩小预览，1.5 倍字号隐藏预览。此前被否决的候选截图均不作为本轮验收证据。

现有回归覆盖普通字号和大字号的等高、142dp 外框、当前码完整、下一组缩小与隐藏、空账号自然上移、复制及隐私遮罩，并直接测量生产列表的间距与菜单操作。设备复用 Monica_Issue136_API_32，不新建 AVD。
