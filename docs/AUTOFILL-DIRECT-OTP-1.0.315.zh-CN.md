# 表单直填后的 OTP 操作（1.0.315，未发布）

表单下拉列表、键盘内联候选选择密码后，沿用已有的“通知栏验证码”和“自动复制验证码”开关。支持密码自带密钥和绑定的验证器，不增加确认页面；关闭开关、无验证码和仅用户名填充保持原直填。

## 稳定性边界

- Android 普通 Dataset 没有选中回调。仅符合条件的实际密码填充使用现有非导出透明回调，返回构建候选时准备好的原始 Dataset，不重新推测表单字段或选择密码。
- 原有锁定验证、取消、手动选择兜底不变。立即返回成功的填充结果，OTP 在应用作用域中异步处理，不等待解密或通知服务；通知权限、频道、服务启动、密钥解析失败不会改成填充失败。
- 回调参数仅使用系统类型和基础类型 Bundle，兼容系统进程及进程重建。保留旧参数读取。实际 Android 12 测试曾发现自定义 Parcelable 会让系统丢掉所有 extras，已修复并增加 Parcel 回归。
- Android 12 起使用 ephemeral dataset，让同会话再次选择也能触发回调。Android 8–11 可能缓存首次回调返回的 Dataset；同会话清空后再次选择不保证重复提醒，新填充会话恢复正常。没有通过更改系统会话或固定内联候选绕过此限制。
- 未修改数据库结构、密码内容、备份格式或 HOTP 计数器。

## 性能

密码自带验证码从已有候选判断。绑定验证器的 ID 索引在服务生命周期内共享后台加载，不缓存密钥或验证码；secure_items、local_mdbx_databases 或解锁状态变化时失效，服务销毁后释放。

新增判断的冷查询最多等待约 100 ms，后台扫描不因单次等待超时而重复启动。密码内置密钥的候选不因绑定扫描超时丢失回调；仅有绑定验证器而首次扫描超时的条目，当次仍保留普通直填，后续请求使用已准备的索引。显示列表前不生成验证码或启动通知服务。

API 32 公共模拟器、隔离用户10、1,000 条加密验证器记录的当前实测：最新普通版与 F-Droid 均为关闭时 P95 3 ms、命中缓存 P95 1 ms、首次等待102 ms。此为新增资格判断耗时，不是整个 Android 候选列表出现耗时；不同设备会不同。瓶颈是重复读取和扫描，当前无需引入 Rust。

## 验证

最终测试汇总和构建文件哈希见同目录 autofill-direct-otp-315-verification.json。回归覆盖 API29/34 Dataset/Parcelable，真实 API32 的下拉、IME 内联、WebView、分步表单、验证/取消、无效验证码及原输入焦点行为。两版本各152项自动填充单元测试通过。测试仅使用合成记录并还原系统与应用配置。没有在所有厂商及所有旧系统上穷举验证。

最新 APK：普通版13项重点回归全部通过（首次6项通过，其余7项被模拟器用户切换后的锁屏挡住，修正测试前置检查后在同一APK补测全部通过）；F-Droid 完整31项回归全部通过。普通版异步调整前的完整31项通过记录单独保留，不冒充最新APK的完整测试结果。失败日志、重试及APK哈希均保留在验证记录中。公共模拟器隔离用户的自动填充、输入法和无障碍设置已核对还原，恢复原前台用户0并停止本任务启动的模拟器，保留数据盘。
