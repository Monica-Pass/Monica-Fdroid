## WebDAV：已复现并修复的并发退避问题

两个客户端共用同一主机的退避状态。当备份请求收到 503 / Retry-After 后，之前已在途的同步请求返回 200，会无条件清除该主机的等待。这样后续请求可能过早发出。

`recordSuccess` 现在只清除已经过期的退避，不提前解除有效的 Retry-After 或临时禁用。原有退避时长、重试预算、ETag 条件写入及文件保护逻辑不变。

回归测试使用真实 WebDAV 客户端工厂和共享状态、两个独立客户端、受控的本地 HTTP 服务，以锁存器固定返回顺序。修复前在“成功请求不应取消 Retry-After”断言失败；修复后成功，后续重试在本地被阻止，服务器总请求数保持 2。另验证 5 分钟退避、超过 5 分钟的服务器等待、主机隔离及到期恢复。

## 对用户现象的判断

“先提示稍后重试，等待越来越长，最终 503”与限流／服务繁忙及退避相符，但缺少这次服务端响应和请求日志，不能证明最初失败必然由 MDBX 引起。MDBX 增量同步需要目录、分段和版本检查，多设备及多代数据会增加请求数；现有代码已复用已验证的父目录，重试有次数和总等待预算，没有移除数据一致性校验来减少请求。

测试只使用合成数据和本地模拟服务，没有向用户云账户发送请求。它验证了客户端请求及失败保护，不能替代用户网络、真实限流配额或远端服务状态的实测。
