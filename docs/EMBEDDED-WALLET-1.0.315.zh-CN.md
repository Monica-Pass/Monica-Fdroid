# 项目内银行卡与笔记副本（1.0.315 未发布）

银行卡和笔记的复制、完整编辑器、父密码保存及独立详情已接入。支付信息直接打开银行卡编辑器，隐藏数据库选择；复制已有项目使用选择 sheet。普通备注与复制的完整笔记分别保留。

## 数据与保存

- 受保护自定义字段 `monica.content.wallet.bank_card`、`monica.content.wallet.note` 存储版本化 JSON。`version/kind/id/title/notes/favorite/data/assets` 构成快照；`data` 保留原项目资料和未知成员。
- 资产归属于目标 PASSWORD owner。每个资产使用独立 `wallet-*` 名称，记录显示名、MIME、用途、长度和 SHA-256。卡面、正反面照片、普通附件和 Markdown 图片不再依赖来源项目的附件行或图片路径。
- 源文件先完整读取到加密暂存区，成功后才替换草稿；按每个保存目标分别上传。新快照在附件上传完成后才写入目标；修改已有副本时，上传失败前保留旧快照和旧笔记引用。失败可重试，重试会实际读取并校验已上传内容。
- 编辑器可导出或移除已复制的普通附件。移除先作用于草稿；取消编辑不修改来源。新图片、卡面和附件仍使用原编辑器的完整功能。
- 新版编辑器对未知自定义字段类型保留原 JSON，并保留已知字段的未知属性。其他客户端应原样保留不认识的快照和字段，不要将其简化成几个支付属性。
- 基础支付信息仍映射到密码项目的自动填充属性；详情存在完整银行卡副本时隐藏重复的基础支付展开区。

## 已处理的问题

修复启动附件清理与“加密完成、数据库记录尚未登记”并发时误删新附件的问题；修复图片缩放解码的初始采样值；兼容只有 PIN 等资料、没有卡号的旧支付信息。新笔记副本成功保存后才替换旧绑定。

## 验证范围

最终构建、单元测试、设备测试、APK 哈希和源文件哈希见同目录 `embedded-wallet-315-integration-verification.json`。设备测试使用公共 API 32 模拟器，保留现有数据和显示设置。

覆盖：完整文件字节、重复保存、两个目标密码、删除来源后读取、真实卡面图片解码、未知字段、Markdown 图片引用、Local/KeePass/MDBX 延后发布、完整银行卡/笔记编辑器，以及密码页面选择副本和打开独立详情。

本轮不把 Bitwarden 在线附件服务、所有服务端限制、不同客户端的备份恢复及进程强杀故障注入视作已完成验证。证件和账单地址的完整副本编辑器、默认内联 OTP 字段仍属于后续任务。多目标保存是逐个目标提交，不是跨数据库事务。
