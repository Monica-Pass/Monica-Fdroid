## 行为

- 页面调整自定义中的四组排序列表去掉六点拖柄和上下按钮；长按整行拖动，保留开关和读屏上下移动操作。
- 新建／编辑密码的按需内容使用同一 Reorderable 库的 LazyList 实现。普通内容和同类重复内容块可混排，卡片跟手移动、邻项让位，支持边缘自动滚动。默认验证码字段及底部添加入口固定。
- **仅被拖卡片四角、上方邻卡下边、下方邻卡上边变为 24dp**；其余相邻边维持 4dp，列表原有外侧圆角不变。邻接关系随位置更新，落位后平滑恢复。
- 保留普通点击编辑、三点菜单和原有删除确认。遵循现有触觉反馈开关；减少动画模式下圆角直接切换、密码列表省略邻项落位动画。

## 保存和数据

拖动只调整编辑草稿的内容顺序，仍通过既有 `monica.content.order` 元数据保存。没有修改数据库 schema、加密、备份或同步格式，也不改变内容块标识、受保护标记、卡面或附件引用。原有详情页继续读取相同顺序。

真实密码编辑测试覆盖笔记、银行卡、地址、12 个重复 API Key 及未知受保护字段：拖动、保存、重开后顺序正确，原内容逐项一致。MDBX 原生文件保存、编辑后重开及未知字段兼容测试通过。

## 实现维护

`DirectReorder.kt` 共用圆角规则、拖动上下文及自然高度行的视觉位置计算。自定义页保留 `ReorderableColumn` 的落位提交；密码页保留原 LazyColumn 和稳定 key，不引入嵌套滚动。

设备测试复现了 Reorderable 3.0.0 的 `Scroller.start()` 启动时序问题：立即调度时，协程先读到空通道退出，已完成的 job 却留在状态里。`rememberDirectReorderScroller` 仅为原 Scroller 提供继承父 Job、使用非 immediate 主线程 dispatcher 的作用域，使滚动请求先入队；移动算法仍由原库处理。

该兼容函数是唯一使用库 internal 构造器的地方，局部使用 Kotlin 可见性诊断抑制。当前固定的 3.0.0 已经过两版编译和设备验证；未来升级 Kotlin／Reorderable 时应复查此构造器，并在上游修复后移除兼容函数。不要删除边缘滚动回归测试。
