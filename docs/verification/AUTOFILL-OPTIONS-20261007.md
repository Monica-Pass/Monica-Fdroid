# 自动填充可选保留与主任务锁定 · 1.0.318

日期：2026-10-07。普通版与 F-Droid 同步实现；未提交或发布。

## 行为

- 设置 → 自动填充 → 自动填充验证：新增“保持解锁两分钟”，默认关闭，仅启用自动填充验证时显示。
- 开启后仅复用同一应用和规范化网站的验证，固定 120 秒，连续填充不续期。关闭、锁屏、主动锁定、移除 Monica 主任务或进程重启后失效；重新开启不会复活旧授权。
- 普通切换应用与配置重建保留原自动锁定规则；新进程和新主任务从锁定开始。开发者主动关闭身份验证的策略保持原样。
- 备份记录开关选择；旧备份缺字段恢复为关闭。恢复设置撤销已有临时授权。密码库内容与主密码不变。

## 原因与修正

原来的主会话会从 SharedPreferences 恢复已解锁状态，包含“永不过期”会话；主任务移除也没有对应撤销检查。自动填充选择器继承的触摸处理还会刷新主会话计时。新进程启动先撤销磁盘旧状态，任务守卫跟踪 MainActivity 及已有启动器任务，在生命周期和授权使用前检查任务是否仍存在；检测失败时不放行已有被跟踪任务。自动填充触摸不再刷新主会话。不开常驻服务、不轮询。

本轮补充了上轮未覆盖的真实任务移除与真实进程重启测试，上轮报告不代表本轮结果。

## 验证结果

普通版与 F-Droid 各 **26 项 JVM + 23 项 API 32 设备测试通过**，共 98 项。两版 debug 应用及 androidTest 构建通过，测试 ABI 为 x86_64。

使用公共 Monica_Issue136_API_32、独立 Android 用户 10；真实加密 Room 测试条目、系统 AutofillManager 和原生页面。具体日志、APK 哈希见本目录附件。

- 固定 120.1 秒真实等待过期、超过旧 30 秒的两步填写、密码选择器重建、单条回调验证、错误密码及取消重试、不同网站隔离、锁屏与显式锁定。
- 默认关闭时下一次填充要求验证；关闭再开启不恢复旧授权；缓存中的被屏蔽请求仍被拒绝。
- 真正打开 MainActivity 并输入合成测试主密码，Android ActivityManager.finishAndRemoveTask 移除真实主任务；后续自动填充要求重新验证，重新打开主页面出现密码输入，主密码可正常解锁。
- 真实主页面配置重建和普通后台切换不误锁；实际密码选择器触摸不延长主会话时间。
- 两阶段 host 脚本：在无限锁定时长下保存已解锁状态和临时授权，执行 am force-stop，再从不同 PID 验证主会话、运行密钥和自动填充授权均失效；没有清空应用数据。
- 原生设置页在 320dp / 1.7 倍字体下切换、隐藏/显示和重建保留状态。旧 ZIP 配置备份缺字段默认关闭，新 ZIP 备份往返恢复开关选择。

初轮 21 项中有一项测试脚本错误：ActivityScenario 默认 CLEAR_TASK 意外删除了主任务。日志确认锁定来自真实任务移除；改为独立任务启动选择器后，F-Droid 的配置重建与触摸断言通过，但框架 moveToState 未把主任务带回前台；改为系统 AppTask.moveToFront 后单独重跑该用例通过。普通版最终完整 21/21；F-Droid 完整轮 20/21 加该项修正后的重跑，共 21 个独立用例通过。两版另各有两项不重装应用的强制停止进程测试。准备进程重启测试时还遇到测试用户切换后系统锁屏未解除，应用正确拒绝授权；改为先在独立测试窗口通过系统 API 请求解锁再准备会话。两次准备失败及清理尝试不计入通过数量。保留失败日志，不把失败尝试计入通过数量。

范围限制：任务移除使用 Android 系统 API，而非每种厂商最近任务界面的手势；未进行 HyperOS 实机或实体指纹硬件测试。本轮没有测试 Android 32 以外的系统。已返回到外部表单的填充值不撤回。
