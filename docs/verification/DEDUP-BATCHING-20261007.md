# 去重合并批次优化（2026-10-07）

## 实现范围

- 普通版及 F-Droid 的去重执行器统一支持最多 100 条的本地 Room 事务；连续的无附件新密码与无附件、无照片的本地安全条目可以合批。继续通过原有 repository 写入，密码与自定义字段处于同一事务。
- 事务提交后才推进批次进度。批次失败时先完整回滚，再逐条重试并报告具体失败条目；取消会传播，不继续重试，当前未提交批次回滚，之前已提交的批次保留。进度仍表示已处理数量（含失败），最终结果分别报告成功与失败数量。
- 附件、图片、MDBX、Passkey 私钥存储涉及 Room 之外的写入，因此保留原有逐条执行及补偿流程，不放入可整体重试的 Room 事务。
- 没有附件时直接结束附件复制，不初始化附件后端或执行空查询；本地安全条目不调用 MDBX 图片持久化。
- 分析时复用已加载的三类条目列表生成来源统计；执行前验证目标可用性时不再额外读取三类完整条目。仍然重新分析计划，避免预览期间新增的目标条目被重复导入。
- 没有调整数据库结构、密码加密格式、去重身份及冲突规则，也没有改变来源记录。

## 诊断基线

详细基线见 [DEDUP-PERFORMANCE-20261007.md](DEDUP-PERFORMANCE-20261007.md)。公共 AVD 为 `Monica_Issue136_API_32`，Android 32 / x86_64。独立磁盘 Room 库使用 854 条合成来源密码（848 个不同条目、6 个重复），目标为 Monica 本地空库。

原实现：无持续列表订阅时执行 2,305 ms / 完整密码查询 3 次；一个持续列表订阅时执行 12,060 ms / 查询 841 次。增加查询次数断言后，旧实现再次以 838 次查询失败，确认回归测试能够拦截原问题。

## 验证方法

- `DedupLocalPerformanceInstrumentedTest`：真实 `SecurityManager` 加密和真实 service 分析、执行，验证 848 条成功新增、来源 854 条保留、完整密码查询少于 60 次。新测试还接入真实附件支持，但数据不含附件，因此不代表远程附件传输耗时。最终性能单独运行，避免与 Gradle 构建争用资源。
- `DedupBatchInstrumentedTest`：用 SQLite 触发器注入自定义字段及安全条目写入失败，检查批次回滚、逐条重试、没有重复副本、字段完整及正确进度；在第二批已写入部分字段时取消真实协程任务，验证第一批 100 条保留、当前批次及字段回滚。
- `DedupMergeExecutorTest`：确认附件、照片、MDBX 和 Passkey 回调不在可重试的本地事务内；保留原有逐条失败、取消和错误文案测试。
- 原有去重、Passkey、MDBX 与数据库组合设备测试：覆盖不同来源、重复导入、预览后变化、私钥仍可签名、照片和附件独立复制、损坏附件回滚、目标不可解锁及来源不变。F-Droid 同步这组设备测试和模拟附件下载端点。

## 最终结果

两版 `:app:assembleDebug`、`:app:assembleDebugAndroidTest` 和相关 JVM 测试构建通过。最终每版 26 个 JVM 测试、44 个设备用例通过，共 140 个；重跑和性能复测不重复计入总数。普通版首轮的 4 个环境失败用例经下述代理修正后重跑通过，强化后的真实任务取消测试也另行运行通过；F-Droid 最终一次完整运行 44 个设备用例全部通过。

构建结束后单独运行性能用例，使用相同公共 AVD 和数据规模：

| 版本 / 场景 | 初次分析 | 执行至首次进度 | 完整执行 | 执行期间完整密码查询 |
| --- | ---: | ---: | ---: | ---: |
| 普通版原实现，一个列表订阅 | 1,233 ms | 1,278 ms | 12,060 ms | 841 |
| 普通版优化后，无持续列表订阅 | 2,037 ms | 1,761 ms | 1,927 ms | 1 |
| 普通版优化后，一个列表订阅 | 1,873 ms | 1,877 ms | 2,150 ms | 10 |
| F-Droid 优化后，无持续列表订阅 | 2,054 ms | 2,075 ms | 2,222 ms | 1 |
| F-Droid 优化后，一个列表订阅 | 1,761 ms | 1,716 ms | 1,953 ms | 8 |

完整执行包含执行前重新分析；初次分析不计入该列。新实现首次进度包含首批提交，旧实现包含第一条提交。每组均新增 848 条、失败 0 条，来源 854 条保留。分析耗时没有宣称稳定提升；已经验证的收益是合并阶段不再因逐条提交反复重查完整列表。查询次数允许随 Room 合并通知的时机略有变化，测试断言使用宽松上限而非精确次数或设备耗时门槛。

这些是无附件的合成数据结果，不是远程附件传输或所有真实设备的性能承诺。附件及跨库行为由独立功能回归覆盖。执行器、service、附件支持和新增批次测试在两版逐文件比对一致。

## 测试环境问题

首轮普通版 44 个设备用例中，4 个 Bitwarden 用例在准备来源数据阶段返回 `502 Bad Gateway`，未进入去重执行。原因是公共 AVD 的全局代理 `10.0.2.2:7890` 把设备内的模拟服务器请求转发到外部代理。临时关闭 AVD 代理后，这 4 个用例重跑全部通过。没有为此修改业务代码或放宽断言；任务结束恢复代理设置并停止本任务启动的公共 AVD。

构建、设备测试及性能日志保存在工作区根目录 `.codex-tasks/dedup-performance-20261007/`。此轮不创建 Release、不修改已发布的 F-Droid 1.0.317/24 历史；发行说明写入普通版 1.0.317 与 F-Droid 下一版，并同步候选说明。
