# Issue #153：自动填充两分钟授权复用验收

日期：2026-10-07。需求：https://github.com/Monica-Pass/Monica/issues/153 。版本：普通版及 F-Droid 1.0.318 未发布。

## 实现

- 已有 30 秒授权改为从验证成功开始计时的固定 120 秒，使用 elapsedRealtime；查询及重复填充不会续期。
- 同一应用和规范化后的网站主机内复用，允许账号页、密码页的字段签名和 Activity 改变。不同应用、不同网站、缺失应用目标不获授权。
- 系统响应解锁、单条凭据验证、V2 手动选择器统一使用授权；选择器重建可复用。仅成功验证创建授权，取消、错误密码和开发者旁路不会创建它。
- 授权归应用进程持有，Android 断开或重建 AutofillService 不清除授权。应用级熄屏接收器、主动锁定及密钥清理会撤销授权；无持久化，进程重启不恢复该授权。
- 每次复用检查屏幕/锁屏状态、密钥是否仍驻留，以及目标和有效期。授权与撤销同步，密钥先清理再撤销授权。
- 复用时避免再次执行主应用计时器检查而清掉刚验证的密钥。未获请求授权时保留原有严格验证。主应用、IME、Passkey 的会话不因这份授权被解锁。
- 无新设置字段、数据库迁移或 UI 布局改动。

共 60 项通过，0 失败、0 跳过。使用公共 Monica_Issue136_API_32 / x86_64、独立测试用户 10，不创建新 AVD。两版测试使用真实加密凭据、Android AutofillManager 和独立进程中的账号/密码表单。

JVM 覆盖：119999/120000 ms 边界、不续期、重新认证新窗口、时间回退、进程新建状态、应用/网站/空目标隔离，以及原有响应认证和 IME 入口回归。

设备覆盖：

1. 主应用设置为立即锁定，账号验证后等待 32 秒，系统服务断连后密码页直接填入；新 Activity 也可复用。
2. 实际等待 120.1 秒，再次请求出现验证，验证后正确填入密码。
3. 手动锁定撤销授权；即使再次载入密钥，旧授权也不能复活。
4. 熄屏、唤醒后仍需重新验证。测试在唤醒前不读取授权，防止读取时的保护逻辑掩盖熄屏接收器缺失。
5. 手动选择器验证、Activity 重建后显示条目，随后系统密码页填入成功。
6. 单条凭据验证返回 Dataset，随后系统密码页填入成功。
7. 原生表单授权不能放行同一宿主的 WebView 网站表单。
8. 错误密码不授权，正确密码可重试；取消验证不填入，重试成功。
9. 原有验证返回表单、关闭自动填充验证后填入行为不变。
10. 四项屏蔽字段回归：缓存请求与缓存 Dataset 均不能绕过屏蔽，其他字段不受影响。

初轮 10 项设备测试中，选择器功能断言通过，但截图被截图保护阻止，整轮因此标为失败。最终仅在独立测试用户中暂时关闭截图保护并恢复原值，完整重跑上述最终测试组；未把初轮失败计入通过数。

## 验证范围

真实设备流程验证了主密码认证。未录入/使用硬件指纹，也未覆盖其他 Android API 或厂商系统；生物识别成功后走相同的授权创建路径。进程重启的授权失效通过进程内存结构和新 store 用例验证，未额外强杀测试进程。

“失效”指后续新请求不再复用这份临时授权。原有主应用会话仍遵循自身策略；本功能不撤回 Android 已交给目标应用的字段内容。
