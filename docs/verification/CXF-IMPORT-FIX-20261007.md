# 应用间凭据导入兼容性修复（2026-10-07）

本次处理[前一轮调查](CXF-IMPORT-DIAGNOSIS-20261007.md)确认的过度拒绝、跳过原因不透明，以及内部应用范围 JSON 被展示为普通字段的问题。

## 行为变化

- Passkey 的扩展缺失、空对象、显式 null、已知可选成员为 null，或仅有 `payments:false` 时，可以继续校验并导入原始凭据。显式 null 是兼容性容错，不声称规范要求接受。
- 包含真实或非 null 的 HMAC／PRF 状态、Blob 数据、启用的支付扩展，或未知／无效扩展时仍跳过。不会丢弃扩展、替换私钥或生成新凭据来制造导入成功。
- 接收页和导入完成摘要显示接收阶段的原因分类：不支持的类型、验证码、无效凭据、私钥格式、PRF、Blob、支付及其他扩展。接收阶段的跳过原因与后续写入失败分开。
- 成功接收时记录解析数量和固定原因枚举；不记录标题、账号、密码、私钥、种子或原始 CXF。
- `CXF Android apps` 保持原名称和原内容存储，用于保留应用范围及签名约束；详情、编辑和键盘普通字段选择不显示它。删除普通字段分组不会删除内部元数据。已有条目无需迁移、重新导入或转换数据库。
- KDBX 仍使用已有 KeePass 兼容 Passkey 格式；目标路由未改变。

## 版本范围

普通版包含应用间传输入口、解析诊断及共享 UI 修复。F-Droid 仅同步适用的共享逻辑、元数据展示和保留行为，不重新接入 Google Play 服务的传输入口。

已记录普通版 `1.0.317`、F-Droid 下一版及两者候选版本的中英文未发布说明。本次没有修改已发布标签或发行历史。

## 验证记录

普通版 26 个 JVM 测试、F-Droid 22 个 JVM 测试通过：覆盖扩展容错、真实扩展拒绝、混合类型计数、日志不包含凭据内容、P-256／RSA／Ed25519 原始密钥往返及签名、目标格式映射。

修复前新增的扩展容错回归测试实际失败；修复后通过。普通版和 F-Droid 的调试包与设备测试包构建成功。

公共模拟器使用 `Monica_Issue136_API_32`，不新建 AVD。设备测试使用合成数据、临时数据库和本机模拟 Bitwarden 服务，不访问真实账号。

普通版首轮两个数据库集成测试通过：四种目标（本地、KDBX、MDBX、模拟 Bitwarden）验证导入、原始密钥签名、跳过原因保留，以及 SHA-512 应用签名约束的导出往返。未匹配证书不会变成无条件应用绑定，原始信息仍保留。

首轮三个 UI 测试因默认测试 Activity 未保留 Compose 页面而失败，不计为通过。改用仅在 debug 中注册的生命周期测试宿主，并修正测试对折叠字段编辑操作的定位后，两版最终设备测试各 5 个全部通过。

最终结果共 **48 个 JVM 测试 + 10 个设备测试通过**。设备验证包括：

- 四种目标数据库的真实写入、原始密钥签名及再次导出，KDBX 兼容模式保持不变。
- 应用范围信息及 SHA-512 签名约束往返，不匹配的签名不会建立关联。
- 320dp 宽、480dp 高、1.7 倍字体下，分类提示能够换行及滚动查看。
- 完成摘要保留接收阶段的原因，并与后续写入失败区分。
- 详情和编辑页面不显示内部 JSON；普通字段可修改和保存；移除普通字段分组后，原始应用元数据仍完整保留。

最终运行结果为 `Main-result.json` 和 `Fdroid-result.json`（各 `completed=true`、`tests=5`），记录所安装应用及测试包的 SHA-256。模拟器测试恢复原 Android 用户及代理设置；任务结束后停止本任务启动的公共 AVD，保留其配置与数据盘。

测试源码：`CxfCredentialCodecTest`、`CredentialExchangeErrorsTest`、`CxfImportUiTest`、`CxfImportCompatibilityInstrumentedTest`。运行日志、测试结果及模拟器截图保存在工作区 `.codex-tasks/cxf-import-fix-20261007/`。
